"아껴 쓰고, 나눠 쓰고, 바꿔 쓰고, 다시 쓰고" — 예전 그 아나바다 맞습니다. 다만 저희가 아끼자는 건 물건이 아니라 우리 팀의 개발 시간이고, 나누자는 건 옆 팀의 노하우, 다시 쓰자는 건 잘 만들어둔 사내 자산입니다.

아나바다현재 업무에 적용 가능한지 근거를 비교하고 활용 방향을 제안한다.

같은 매출 대시보드라도 대상 고객·집계 단위·데이터 연결 방식·접근 권한이 다르면 그대로 사용할 수 없습니다. (설명용 판단 후보이며, 구현된 점수 산식이 아닙니다.)

검색은 "관련 자료나 유사한 자산을 찾는다"에서 멈춥니다. 아나바다는 한 걸음 더 갑니다 — "현재 업무에 적용 가능한지 근거를 비교하고, 활용 방향을 제안한다."

예를 들어 같은 매출 대시보드라도 대상 고객, 집계 단위, 데이터 연결 방식, 접근 권한이 다르면 그대로 쓸 수 없죠. 그래서 결과를 네 가지로 정리합니다 — 그대로 쓰기(REUSE), 고쳐 쓰기(EXTEND EXISTING), 새로 만들기(DEVELOP), 추가 검토(NEEDS REVIEW). 재사용이 부적절할 때 신규 개발이나 추가 검토를 제안하는 것도 이 서비스의 가치입니다.

SCRIPT

판단의 재료는 근거(Evidence)입니다. GitHub·Confluence·Jira·IMS·BizForce·EDM 같은 여러 Source에서, 기능·설계·이력·운영 Risk·업무 Context 같은 근거를 모아 하나의 자산에 연결합니다. 단순한 시스템 목록이 아니라 — 여러 출처의 근거가 하나의 자산 판단을 뒷받침한다는 게 핵심입니다.

그리고 권한. 아나바다는 기존 접근 권한 안에서만 탐색하고, 사용자의 권한을 확장하지 않습니다. 브랜드의 '나눠 쓰기'도 이 권한 범위 안에서의 활용을 뜻합니다. 이번 해커톤에서는 Mock Identity와 Mock Source를 쓰고, Source Adapter를 교체하면 실제 사내 시스템으로 확장할 수 있는 구조를 지향합니다.
