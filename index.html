SCRIPT

여러분, AI로 개발한다고 무조건 시간 아끼는 거 아닙니다. 옆 팀에 있는 걸 또 만들면? AI랑 같이 야근하는 겁니다! 원인은 세 가지죠 — 어디 있는지 모르고, 찾아도 내 업무에 맞는지 판단이 어렵고, 그래서 결국 다시 만듭니다.

그래서 아나바다는, AI가 4가지 기준으로 기존 사내 자산을 찾아 알려줍니다 — 그대로 쓰기(REUSE), 고쳐 쓰기(EXTEND EXISTING), 새로 만들기(DEVELOP), 추가 검토(NEEDS REVIEW). 재사용이 부적절할 때 신규 개발이나 추가 검토를 제안하는 것도 서비스의 가치입니다.

Source → Evidence → Asset → Decision

하나의 자산을, 여러 근거로 판단합니다

SCRIPT

판단의 재료는 근거(Evidence)입니다. GitHub·Confluence·Jira·IMS·BizForce·EDM 같은 여러 Source에서 기능·설계·이력·운영 Risk·업무 Context를 모아 하나의 자산에 연결하고, Advisor가 사용자의 Task Context와 비교해 네 가지 Decision을 산출합니다.

핵심은 단순 시스템 목록이 아니라, 여러 출처의 근거가 하나의 자산 판단을 뒷받침한다는 관계입니다. 그리고 아나바다는 기존 접근 권한 안에서만 탐색하며 사용자의 권한을 확장하지 않습니다. 해커톤은 Mock Source, 실제 환경은 Source Adapter 교체로 확장합니다.
